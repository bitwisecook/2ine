# macOS desktop session identity and Dock ownership

The launcher creates one private immutable application wrapper for each launch session. Its public `CFBundleName` and `CFBundleDisplayName` use the saved launcher title first, an original LX/NE module description second, and the executable stem otherwise. Existing custom/WPS/executable icon decoding supplies bounded RGBA or encoded image bytes to a cache artifact. Optional missing icons do not prevent launching.

`cache/desktop-sessions/<session>/<name>.app` contains a private loader copy, signed together with its final identity and icon resources while preserving original executable entitlements. The original runtime loader is not modified. Dependencies remain pinned by prepare-launch's cache-first host library paths; there is no escaping runtime symlink inside the signed bundle. Cache entries and absolute host paths are not added to the portable manifest. Reused session IDs and symbolic-link cache directories are rejected. `LSUIElement` initially makes the wrapper an accessory application; it is promoted only when it owns a visible GUI window. The child loader path is obtained through the existing public host-executable API, so `DosExecPgm` children retain the same wrapper identity.

The host-only controls `TWOINE_DESKTOP_SESSION`, `TWOINE_DESKTOP_NAME`, `TWOINE_DESKTOP_ICON`, and `TWOINE_DESKTOP_AUXILIARY` cannot be replaced by guest environment settings. The existing child environment builder preserves them. Shared startup processes and REXX service workers are explicitly auxiliary, even if they create a hidden PM window. Console-only processes never acquire the GUI lease.

The first visible process in a session obtains a nonblocking file lease in the ball's existing IPC directory and becomes a regular AppKit application. Other processes remain accessory applications, with normal visible windows and focus. Demotion occurs before releasing ownership. Hiding/destroying the last visible window releases the lease; process exit/crash releases it in the kernel. Peers check for ownership while processing events, with a maximum 100 ms idle check interval. A failed AppKit demotion retains the lease rather than allowing duplicate leaders. There is no process-name killing, PID adoption, global daemon, private LaunchServices rename, or SDL delegate replacement.

Public contracts: [SDL MAC_BACKGROUND_APP](https://wiki.libsdl.org/SDL3/SDL_HINT_MAC_BACKGROUND_APP) must be configured before SDL video initialization; [AppKit activation policies](https://developer.apple.com/documentation/appkit/nsapplication/activationpolicy-swift.enum) distinguish regular Dock/menu applications from accessory windows; [applicationIconImage](https://developer.apple.com/documentation/appkit/nsapplication/applicationiconimage) supplies the runtime Dock image. Platform-specific AppKit code stays in `hal/macos`, while the visible-window/lease state machine is directly exercised by platform-independent tests.

## Cmd-grave window cycling

Cmd-` and Shift-Cmd-` now use one stable eligible-window cycle within the launch session, including independent guest processes. This follows [Apple's window-cycling shortcut](https://support.apple.com/en-gb/102650). A local NSEvent monitor consumes the host command before SDL delivers guest keys. Other modifier combinations remain guest/native input. An unavailable/busy registry or a single eligible window safely does nothing; it does not fall through to native cycling of deliberately excluded dialogs.

The bounded session-private registry supports 64 live members and 256 eligible windows. Random member tokens and kernel lifetime leases distinguish process incarnations without adopting arbitrary PIDs. Registry writes use atomic replacement under a nonblocking guard. The target's owner polls its own activation request; superseded requests have serial numbers and cannot later steal focus. The source uses public [cooperative activation](https://developer.apple.com/documentation/appkit/nsapplication/yieldactivation(to:)) for the matching session bundle, and the target uses `activate` and `makeKeyAndOrderFront:`. Only each process's own SDL/NSWindow instances are enumerated; no global window inventory or broker is introduced.

PM emits generic HAL eligibility/modal metadata during creation, show/hide, enable, reparent and modal-loop transitions. Dialogs, menus, disabled roots, native panels, minimized windows and popup/tooltip windows are excluded. Any guest modal, native AppKit modal or attached sheet blocks the group command, including its matching keyup. Moving a modal child updates both old and new roots. Native AppKit focus notifications refresh the cursor immediately; focus changes do not reorder the cycle.

Checks: `twoine_desktop_cycle_tests` directly tests the production selector and registry: forward/reverse/wrap, same-process windows, separate-session isolation, peer requests, peer modality, superseded requests, crashed-member removal, bounded input and nonblocking guard contention. The native PM dialog fixture reads the actual emitted HAL policy before/after dismissal and during modal-child reparenting. The final combined cycle/group/dialog/API/DIVE/video/audio set passed 7/7 in 13.65 s; the added old/new-root reparent regression and cycle fixture passed 2/2 in 0.94 s. Logs: `/tmp/2ine-cycle-final-build.log`, `/tmp/2ine-cycle-final-tests.log`, `/tmp/2ine-cycle-reparent-tests.log`. All owned C/Objective-C files pass clang-format. Native Cmd-` visual/focus acceptance remains pending; these headless checks do not claim it.

The clean isolated release runtime passed the generated child-wrapper gate individually with the documented dummy profile (6.09 s), then both generated LX gates passed together without driver overrides (3.78 s).
