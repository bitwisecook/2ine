# Optional native MT-32 backend

User requested Roland-style MIDI and explicitly accepted Munt. Default General
MIDI remains the complete GeneralUser GS bank; a native MT-32 device is pre-GM
and cannot correctly receive Doom's GM program numbers without a separate map.
No official Munt GM conversion layer was found in the selected public API.
The new backend therefore requires explicit mt32 selection and preserves native
channel/program/SysEx data. The primary agent owns the shared backend selector
and MIDI parser integration.

Official source: https://github.com/munt/munt/tree/libmt32emu_2_8_3/mt32emu .
Pinned download: https://codeload.github.com/munt/munt/tar.gz/refs/tags/libmt32emu_2_8_3
SHA-256 81f8c462f46bc8901618762ae34cf9de93894ff81f41db73c79472fa3baef875.
The official tag object is 008feb32227a16bad343573b33da2196656b8e93.
Source README and c_interface/c_interface.h establish stable C API, full ROM
identification, stereo float rendering and output samplerate conversion. The
API play_sysex_now accepts a complete F0...F7 message; write_sysex is a distinct
inner-body API and is not used. Immediate event/render calls require serialized
access, supplied by the multimedia owner. Native MIDI events pass unchanged.

Files: cmake/Munt.cmake, os2libs/midi_mt32.c/.h,
tests/os2libs/test_midi_mt32.c and docs/midi-mt32.md. Optional build defaults OFF.
When enabled, Munt2.8.3 builds statically with C-compatible API, internal
resampler and PIC; native worker adds -m32. Offline source version is checked.
Runtime paths read TWOINE_MT32_CONTROL_ROM and TWOINE_MT32_PCM_ROM, falling back
to audio.conf mt32_control_rom/mt32_pcm_rom. Missing paths, negative load results,
incorrect ROM types and failed pair initialization return NULL with diagnostics.
A disabled build reports explicitly that MT-32 support is absent. No fabricated
ROM hashes or synthesis-success result is supplied.

A bounded filename search under /home/jimd found no matching MT32/CM32L ROM
images; the user subsequently confirmed no ROMs. Real-ROM audio is unverified.
The --rom-smoke test fails if explicitly invoked without valid supplied ROMs.
No completion marker for real MT-32 audio was created.

Isolated source/build state: .state/2ine/doom/munt/ . The verified main Doom
runtime snapshot was not edited or rebuilt by this subtask. Probe config/source
uses the actual backend and official Munt source, with a NULL config lookup stub
for isolated path-negative tests; full config integration is owned by the parent.
Portable64 Release build and missing/invalid-ROM contract pass. Native i386
Release build and the same contract pass. Disabled build contract passes.
Missing/invalid ROM tests execute real Munt context construction and SHA-based
ROM identification. These are negative contracts, not rendered audio evidence.
