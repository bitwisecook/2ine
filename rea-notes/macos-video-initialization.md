# Native display initialization and shared cursor resources

Build 23 reported repeated `Video initialization failed: No available video device` when Lotus Freelance's preloader thread requested the standard wait cursor. The original private dummy-display trace establishes the chain `LoadCursor(0, 0x7f02)` → `open32Presentation` → `WinInitialize(0)` on a background native thread, before the main UI thread initializes PM. The controlled SDL-only worker fixture reproduces that exact error: actual native main-thread status is false, although SDL regards its first caller as its main thread.

SDL 3.4.18's [Cocoa_CreateDevice](https://github.com/libsdl-org/SDL/blob/release-3.4.18/src/video/cocoa/SDL_cocoavideo.m) rejects background-thread initialization before registering AppKit. [SDL_video.c](https://github.com/libsdl-org/SDL/blob/release-3.4.18/src/video/SDL_video.c) replaces that bootstrap rejection with the generic error seen by the user. This is not evidence that the Mac lacks a display device, and no dummy fallback is introduced.

Standard `LoadCursor` now acquires an actual process-shared typed PM pointer resource without creating a thread anchor or native display. Native cursor realization occurs when it is selected. Repeated acquisitions reuse the same resource and preloader-thread exit does not destroy it. Copied pointers retain their existing owner/destroy semantics; shared system resources are closed by PMWIN's real module-deinit entry point, with an idempotent native-unload fallback. This matches the resource caching and shared lifetime documented by [LoadCursor](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-loadcursorw) and [DestroyCursor](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-destroycursor).

HAL cursor descriptions retain their copied pixels/shape independently of SDL cursor objects. Video shutdown invalidates native cursor realizations, so a shared resource can be selected again after display reinitialization. Cursor state is serialized with the existing video lock. Off-main native cursor cleanup is queued without blocking the worker; an unavailable queue leaves the native object under SDL's shutdown ownership. A background-first native Cocoa display request now fails with a specific main-thread diagnostic before it can register the wrong SDL thread. This does not claim support for creating arbitrary native windows on background OS/2 threads; that needs a broader event-pump architecture if encountered.

Open32 `SetCursor` keeps guest current-cursor state separately from host presentation. A valid typed cursor changes that state and returns the previous guest handle, including on a headless backend without native cursor support; unsupported host presentation remains distinguishable by error 50. Invalid cursor handles return error 6 without changing state. The generated desktop fixture retains its original previous-handle assertion and additionally checks valid nonzero acquisition and invalid-handle state preservation. Cursor lifecycle, generated desktop APIs and Open32 APIs passed 3/3 in 3.69 s (`logical-cursor-tests.log`).

The session wrapper also had a separate signing defect: a copied standalone loader signature did not seal its new plist/resources, and strict signing rejects an escaping `Contents/Resources/Runtime` symlink. The complete private bundle is now signed asynchronously with original entitlements preserved and strictly verified before launch. Dependencies use the existing pinned runtime environment. Existing user caches are not repaired or overwritten; new sessions receive new valid wrappers.

Qualified evidence in the private release checkout:

- `build-video-regression-current/sdl-worker.log`: exact background-first SDL failure, no user windows.
- Original private Freelance trace: worker first native video initialization has `nativeMain=0`, `SDLMain=1`, prior SDL flags zero; explicit dummy succeeds, later main GUI initialization is on the real main thread. The independent `MEM_BAD_POINTER` assertion persists under successful dummy initialization and is a separate allocator investigation.
- Signing fixtures: 3/3 passed in 0.75 s (`signing-final-tests2.log`), covering original executable bytes unchanged, entitlement boolean preserved, spaced paths, strict validation of completed bundle, and rejection of changed plist/icon bytes.
- `cursor_resource_lifecycle`: 1000 repeated worker acquisitions without SDL video, cross-thread resource lifetime, genuine main-thread selection path under an isolated fake cursor backend, display shutdown/restart, shared-destroy rejection and native module cleanup. The fake cursor backend plus dummy display never reads or changes the desktop cursor.
- Cursor lifecycle, PM rendering, PM dialogs, Open32 APIs and PM threading: 5/5 passed in 6.88 s (`cursor-tests7.log`).
- Signed Accessory-only native fixture: worker acquisition leaves video uninitialized; subsequent actual-main-thread `WinInitialize` succeeds with driver `cocoa`, and a native system cursor object can be created/destroyed. Exit 0, `native-display.log`. It creates no windows, selects no cursor, and does not activate or modify user applications.

All diagnostics are under `build-video-regression-current` (ignored build artifacts). The user's Documents ball and existing application processes were not modified or started. Native visible window/Dock/cursor behavior remains a separate acceptance step after the unified build.
