# Full OS/2 media extraction and legacy ZIP codecs

The 2026-11-03 user requests media navigation through nested containers without
unpacking entire intermediate ISO/ZIP images, plus complete selective imports.
This is application tooling; no original-OS reconstruction gate is asserted.

## Original-media evidence and fixes

The 4.52 Client disk-one ISO contains `cid/server/ibmls/IBM500R8/GUIBASER.ZIP`.
Its NETAPI32.DLL is ZIP method 6 (Implode), general flags zero, 63636 bytes
uncompressed and 56078 compressed. NETAPI.DLL in the same archive uses method 6,
271612 bytes uncompressed and 232904 compressed. libarchive lists these entries
but does not supply their decompressor. This is genuine ZIP Implode, distinct
from PKWARE DCL Implode/Blast.

HWZIP 2.4 supplies the established decoder, with unchanged upstream codec source,
its public-domain dedication/Unlicense, project catalogue entry and packaged
license. Source: https://www.hanshq.net/files/hwzip/hwzip-2.4.zip ; SHA-256
5a3fecfaf362972673d40ca0611622cfa94170c70029fbd8c9aa64a9e7d387ac.
The included `tables.c` was generated by upstream generate_tables.c as documented
in its README. Original notices are retained, rather than reclassified as newly
AI-authored code.

`ball/zip_legacy.h` adapts the codec to the existing read-at stream. It checks
central/local metadata, input/output bounds, selected names, sizes and CRC-32;
only the selected compressed member is decoded into memory. Legacy compressed
members have 16 MiB input and output bounds. Stored members remain direct slices
with no complete-image decode; other compression uses the existing lazy reader.
The parent archive/ISO is never materialized to disk by this adapter. ZIP64 and
multivolume legacy archives are not implemented by this adapter; libarchive
continues to handle the formats/codecs it supports.

Two further original-media cases shaped the checks. libarchive's seekable ZIP
`archive_read_header_position()` reports 50 for the second NETAPI member whose
actual local header is at 56128. The adapter therefore resolves a normalized
selected name against the checked central table, not that position hint.
`books/infzip/sg244640.zip` has reserved bit15 in its local flags (0x8000) but
central flags zero; its 3964077-byte INF correctly decodes and validates its CRC.
Only decoder-significant flag differences are rejected. The original
`books/pdf/rbsample.zip` uses ZIP Shrink (method1) for `backdasd/dos.bat`
(153 uncompressed,133 compressed), so HWZIP's unchanged Shrink and Reduce
methods were also integrated. All legacy methods 1–6 now use verified sizes and
CRC. PKZIP1.01/1.02 minimum-length compatibility is retried only if complete
length and CRC both verify.

Native adapter NETAPI32 output SHA-256 matches independent system Info-ZIP:
0baac280dcdd5831862578b55be7e3abdb26856f01b805320741b66c07df5c36.
The raw compression fixtures and comparison tools are ignored local `/tmp`
artifacts; no IBM binaries are committed.

## Ambiguous full-distribution versions

The original disc ships mutually exclusive Win-OS/2 language/display payloads.
WINSHELD.EXE alone has multiple different same-priority payloads. Full import
without a module filter now preserves each distinct ambiguous version at
`C:\OS2\INSTALL\MEDIA\<content-sha256>\<filename>`, leaves its disputed usable
canonical destination unset, and records original destination, source and SHA
in `preservedVariants` plus cumulative `logs/os2-extraction-variants.json`.
Identical alternatives coalesce. Existing variant files are accepted only if
their hash matches; existing differing destinations remain protected. Selective
category imports and dependency module repair retain strict version-conflict
errors rather than choosing an unknown DLL release. Existing explicit source
priority rules were not changed by this fix.

## Hobbes format follow-up

The primary Hobbes mirror directory
https://mirror.math.princeton.edu/pub/hobbes/os2/util/archiver/ lists native ARC,
ARJ2/UNARJ, ACE and other tools; these are established OS/2-era formats, not
inferred only from an arbitrary extension. Existing libarchive does not decode
ARC/ARJ. Deark has substantial complete ARC and ARJ modules plus shared LZH/LZW
engines; a new in-memory bounded adapter is a separate active task. Merely adding
an extension to a frontend filter is not evidence those formats are supported.

## Bounded Hobbes-era ARC, ARJ and Zoo support

The common-format follow-up is implemented in `legacy_archives.h` and
`zoo_archive.h`. Shared source discovery now recognizes `.arc`, `.arj` and
`.zoo`. Walkers read checked directory/member metadata through the existing
read-at abstraction. Selected compressed members alone decode into bounded
memory; no helper process or full intermediate-container extraction is used.
The new adapters add no linked dependency. Names retain the enclosing archive's
ordinary legacy byte encoding; additional OEM/Unicode filename conversion is
not qualified by these ASCII fixture checks.

ARC methods1/2 stored,3 RLE90,4 squeezed Huffman+RLE90,8 dynamic LZW+RLE90 and9
squashed LZW are supported. The common LZW streams use libarchive's established
Unix-compress filter with verified ARC framing/CRC-16. Obsolete ARC5–7 static
modes are explicit unsupported extraction errors; metadata remains browsable.
Later special ARC extensions are not advertised. ARJ supports stored and
methods1–4, checked header/extended-header CRC-32, names and member CRC-32.
Encrypted/multivolume ARJ is rejected. ARJ1–3 use checked canonical LZH decoding,
including the zero block count's65536-symbol meaning. Method4 uses checked
literal/back-reference decoding. ARJZ's51 variant selects the larger dictionary.

An attempted LH6 wrapper proved insufficient: independent 7zz accepted the
same synthetic OS/2-host ARJ1 fixture, whereas libarchive's LHA reader rejected
it. The adapter therefore does not depend on that unsuccessful bridge. The
original ARJ encoder source was fetched for an independent host build, but its
legacy message generator trapped on this macOS host; no successful native ARJ
encoder run is claimed. `/tmp/2ine-arj-native-build4.log` records that limit.

Zoo header types1/2 and methods0 stored,1 LZD and2 LZH are supported. The checked
linked-directory traversal detects cycles, validates type2 header CRCs, honors
long filenames/directories and skips deleted records. Member data must match
CRC-16 and declared size. LZD has checked dictionary indices/lengths and clear/
EOF codes; LZH shares the checked canonical engine with the appropriate Zoo
parameters. Unknown header/method types are rejected. The ARC/ARJ/Zoo selected
member input/output ceiling is16MiB; archive directory walks remain bounded at
100000 members. Multi-volume/encrypted archives and ACE are not advertised as
supported formats.

The codec contracts were checked against the primary Deark source at commit
c19b47c80a5ff8a7b41eb4f578e1afdda99202a2 (ARC, ARJ, Zoo and LZW/LZH modules):
https://github.com/jsummers/deark/tree/c19b47c80a5ff8a7b41eb4f578e1afdda99202a2 .
The new framing/checking implementations are separate code; no Deark source is
linked by these adapters. The original Zoo2.10 decoder/source distribution was
also consulted through Debian's archived original source:
https://archive.debian.org/debian/pool/main/z/zoo/zoo_2.10.orig.tar.gz .
Its extract-only routines carry their public-domain declarations; this does not
relicense the historical archiver program as a whole.
