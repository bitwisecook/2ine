# Lotus imports outside PMWINX

Static audit of private checkout `bad21aa8c184bc635b6035b2bbd5c1df76a46c6b`, reading the installed Lotus ball without modifying or executing it. The shared inventory hashes 411 binaries: 49 in the five executable roots' static closures, 362 additional installed/optional closure records, zero import-parse errors and one unsupported-format record. A later independent export-metadata pass identifies one malformed nonresident export-name table in `WORDPRO/INIEDIT.EXE`; its imports are still fully decoded. Static presence does not prove an API executes or that an optional library loads. In particular `123W.EXE` is a small bootstrap. This initial snapshot counted `MAIN123W.DLL` outside the literal static closure; retained original startup evidence in `rea-notes/lotus-123-startup.md` proves that bootstrap dynamically loads it. `OR1C30EN.DLL` initialization is likewise observed in `rea-notes/lotus-startup-exports.md`. The reusable inventory now records these as provenance-backed known-dynamic roots, distinct from both statically reachable and merely installed optional libraries. The expanded reusable census separates 49 static binaries, 9 additional verified-dynamic-only binaries, and 353 optional binaries. Counts below remain tied to the exact initial hashed snapshot, not an implied complete runtime closure.

Evidence: `build-lotus-coverage/imports-snapshot.json` preserves the inventory used here; `non-open32-coverage.json` records all relevant importers/applications, binary and source hashes, exact ordinal/symbol/source locations, provider decisions and 23 reviewed semantic risks. `missing-exports.csv` contains the complete missing-entry list. The source inventory is generated by `tools/lotus_imports.py`; the independent patched REA/Ghidra overview of `123W.EXE` is retained as `rea-123-inspect.json` (evidence `ev_29cd99981e21d8c91b3bda5754bf25f84e134226db2ba49f5feea9fb2c5097dd`, binary SHA-256 `abfc454dce6fe9acd7a375d0a9f03698fa1469e3c2b5127bbc101f3fc78e5e99`). No decompilation or runtime reachability claim is inferred from that overview.

## Work to prioritize

1. **Thread control and timer/mutex queries:** DOSCALLS `#237 DosResumeThread`, `#238 DosSuspendThread`, `#290 DosStopTimer`, `#336 DosQueryMutexSem`, `#351 DosStartTimer` are absent and statically imported by WordPro/shared Approach/Organizer components. `#161/#162` fast-RAM semaphores and `#547 THK_UNITHUNK` additionally appear in original Unicode/C libraries; they require authentic ABI investigation, not generic success returns. Other optional gaps are `#222 DosSetFSInfo` and `#292 DosSetDateTime`.
2. **GPI drawing, transforms and metafiles:** 57 missing imports include path construction/stroking/filling (`#354/#387/#392/#554`), model transforms (`#468/#538`, rotate `#566`), palette handling (`#577/#578/#579/#594/#597`) and metafile querying (`#465/#466`). Core shared libraries import these as well as optional WordPro drawing/filter modules. Existing exports `#375/#401/#411/#428/#536` explicitly reject metafile/boundary work in `os2libs/pmgpi/help.c:7–49`; `#520` accepts only the identity view matrix and `#521` only display-enable control. Present entrypoints therefore do not establish metafile support.
3. **Actual PM drag/drop and font dialogs:** PMDRAG implements string handles only; 15 imported drag-info/transfer/drag-loop APIs are absent (`#32/#34–36/#38–42/#45/#46/#53/#54/#57/#59`). PMCTLS `#2 WinFontDlg` and `#3 WinDefFontDlgProc` are absent, imported by `LTCPRR10.DLL` in Approach/Freelance/Organizer closures. These need real dialogs and transfer lifetimes.
4. **Shared PM behavior:** 34 PMWIN gaps include WordPro's direct `#712 WinCpTranslateString`, Freelance's `#857 WinSetCp`, Organizer's `#921 WinSetKeyboardStateTable`, plus shared-component `#774 WinIsWindowShowing`, `#832 WinQueryUpdateRegion`, `#863 WinSetMultWindowPos` and `#942 WinCreatePointerIndirect`. Present `WinSendMsg#920` resolves caller-anchor windows only (`messages.c:732`), and hooks `#927/#928` support caller-queue HK_INPUT only (`hooks.c:11/27`). Global hooks or synchronous cross-process sends remain separate semantic gaps; the imported function does not reveal requested arguments.
5. **SOM daemon/WPS integration:** PMWP `#480 WinIsSomDDReady` always returns FALSE and `#464 WinRestartSomDD(TRUE)` returns 50 (`pmwp.c:429–437`), even though the frontend can own an original SOMDD service. Both are statically imported by `LTOLSO20.DLL`. Native `#286 WinOpenObject` and many optional SOM/WPS class-data/new-class exports are absent. The implemented folder/program registration store is not the original WPS SOM class system; data exports must not be replaced by callable stubs.
6. **Optional multimedia/printing/networking modules:** MMIO `#28/#29/#30/#77` read/write/seek/header are absent in `PLAYER/GDMPOS2.DLL`; existing `mmioOpen#27` handles MEM elements only (`mmio.c:20`). MDM `#1` supports explicit video/PCM/MIDI command subsets, `#2` string commands are video-only (`mdm.c:657/885`). PMSPL `#441 SplEnumPrinter` and SO32DLL `#4` (symbol not yet mapped) are missing in optional libraries. Existing spooler queries enumerate/query the two PDF/PCL virtual devices, not arbitrary original driver services.

Two smaller present-body issues are DOSCALLS `#14 Dos16SetSigHandler` (zeroes previous fields then reports success without installing a handler, `exceptions.c:118`) and `#418 DosAcknowledgeSignalException` (unconditional success, `exceptions.c:145`). `DosSetPriority#236` changes own-thread guest TIB metadata only, rejecting other scopes/targets (`threads.c:526`); `DosError#212` always returns generic failure (`exceptions.c:138`). These are explicit source findings, not assertions that Lotus reaches each path.

## Original OS/2 providers

SOM and HELPMGR are not counted as policy-provided native gaps. The build contains an empty native SOM placeholder, but the ball supplies the original SOM family; original HELPMGR plus its resource companion supplies the viewer. The selected ball's `SOM.DLL` hash is `1145626f7782d55c0559f9ef96a727752d6c263e6f1058dd35f2f40453dece06`; `HELPMGR.DLL` is `14fae446692c31905461b5b960ef57c4785870476829e3e9da9818f53f0b9d37`.

Native HELPMGR `#51/#52/#54` deliberately fail rather than render help; its optional `#53` is absent. A missing original provider therefore has a real consequence, but extracting original files is a different remedy from adding native exports. The loader searches guest DLL paths before native modules (`loader/modules.c:669–728`), except explicitly selected provider overrides such as Mesa OpenGL/TLS. It selects a module, not an automatic per-function fallback. Do not copy original PMWIN/PMGPI over supplied native services as a blanket repair.

No runtime implementation was changed for this audit. The immediate next step is to bind a failing feature to its actual entrypoint/arguments, then implement and test that bounded SDK contract; the complete static list remains available for planning and offline lookup.
