# Dependency index and Lotus startup compatibility

Version 0.5.1 separates install-time discovery from ordinary cached launch status. Dependency scans occur on installation, adding/changing an application program, component installation/removal, file import, and explicit Rescan Dependencies. Normal launch, refresh, configuration editing and component-pane entry consume saved JSON without walking executable trees, reading import tables, inspecting media or automatically recovering files. Full audit logs remain available, while cached launch closure follows only the selected application/interpreter and configured services. Existing full audit JSON can supply a read-only legacy fallback. Unknown metadata warns without forcing media selection. See `cached-launch-dependencies.md`.

The user's Word Pro installation has a full audit of 595 binaries, 19 missing libraries and 24 unreachable imports. Its cached Word Pro startup closure has 16 records, no missing/unreachable dependencies, and reads in 0.004804 seconds without changing the user ball. The missing optional connectors and unrelated tools remain in the full report rather than becoming startup requirements.

Reported native video failures stem from loading a standard cursor on a preloader thread. Standard cursor acquisition is now display-independent and process-shared; native realization is deferred, logical cursor state and native presentation errors are separate, and display restarts invalidate old SDL cursor objects. A signed real Cocoa no-window fixture passed the original worker-load/main-init pattern. New session wrappers are sealed and strictly verified before launch, with original entitlements preserved and runtime closure resolved through existing pinned environment settings. See `macos-video-initialization.md`.

Freelance's independently reproducible MEM_BAD_POINTER was traced to original SmartHeap's64 KiB pool-header masking. Guest DosAllocMem now selects64 KiB-aligned bases while retaining 4 KiB length rounding; generic/exact loader mappings remain unchanged. Existing shared allocation alignment is preserved. The new real LX guest fails installed build 23 at its first alignment check and passes the corrected runtime; original Freelance passes its former bad-pointer site unchanged. See `freelance-memory-alignment.md`.

PMWINX ordinal 729 RegisterClassAlias and 600 SetClassLong now have guest bindings and class state semantics. CW_USEDEFAULT width selects both default dimensions and ignores the supplied height, preventing Freelance's enormous native backing-surface request. The Open32 TLS family 692–695 uses the verified original 64-slot model, per-thread opaque 32-bit values, reuse zeroing and explicit error/cleanup semantics. GetCurrentThread 258 publishes the calling-thread pseudo-handle. Generated guest tests cover the API contracts; see `approach-class-alias.md` and the TLS evidence note.

This is startup progression rather than qualification of complete applications. OriginalFreelance reaches a later missing LoadAccelerators 457; Approach progressed through the TLS family to GetCurrentThread 258 before that entry was added. Predefined Open32 control classes and remaining dynamic APIs are not qualified by import availability. No original Lotus binary was patched, and actual user applications/balls were not launched, signalled or repaired during testing.

Final test commands/results and signed installed-artifact receipts are retained under `build-evidence/releases`. Intermediate failing fixture-generation, obsolete-audit assertions and reused per-test timeout budgets were corrected before final qualification; they are retained in build-ui-release logs rather than being described as passing runs.
